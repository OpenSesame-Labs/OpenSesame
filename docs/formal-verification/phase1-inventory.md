## Vault row, from the code

`VaultStore.#build` calls `buildVaultState` and `StoreView.publish` stores that object. `getSnapshot` returns the last published object, not a live read of the fields. The screen can change only at a publish.

Published pairs that matter:

- Create (`#persistNewVault`) and `createGuest`: header set, key set, parked key cleared, then publish. Status `unlocked`, second step not waiting.
- Primary unlock with a second step (`#afterPrimaryUnwrap` when `hasSecondStep`): parked key set, vault key unset, then publish. Status `locked`, `awaitingSecondStep` true.
- Second step confirmed (`confirmTotp` and the other confirm paths call `finishSecondStepUnlock`, then `requireTrusted`): the parked key is cleared. With no circle, `activate` sets the vault key, clears the parked key again, and publishes on completion. Status `unlocked`, second step not waiting. With a circle, the publish before approval has no vault key and no parked key, and `trustedUnlock` is set.
- `lock`: `StoreUnlockSession.reset`, then `#clearLockedSessionState` drops the vault key and the parked key. A guest lock also drops the header. Publish follows.

`awaitingSecondStep: pending && !open` is the screen rule. Clearing the parked key before the open publish is the session rule. Both are invariants in the phase 2 model. Neither was weakened to make the check pass.
