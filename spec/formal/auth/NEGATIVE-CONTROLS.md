# Authentication negative controls

Run the mutation checks from the repository root after installing the Node
dependencies and Lean 4.24.0:

```sh
OPENSESAME_LEAN_BIN=/absolute/path/to/lean \
  python3 spec/formal/auth/negative-controls.py
```

The command first runs `scripts/test/auth-formal.sh` against the current
checkout. It copies the implementation files and conformance test into a unique
temporary directory under `work/`, links the installed `node_modules`, and
checks that the copied suite passes against vectors generated by the same Lean
axiom check as the normal gate. Each mutation is then applied to one copied
source file at a time. The check requires a failing Vitest assertion in the
relevant session, principal, or project correspondence tests. It restores the
copy after each mutation, reruns the copied baseline, removes the temporary
directory, checks hashes of the original copied files, and reruns the full live
baseline. No product source file in the active checkout is mutated. The command
fails if a mutation point is absent or ambiguous, a baseline fails, or an
expected assertion is not observed.

The ten controls disable or alter the session token prefix, session mapping,
expiry boundary, revocation, suspended-principal and closed-principal checks;
the provisional-principal guard; the project role proof; and project state and
expiry checks. A changed guard should prompt review and an update to its control,
not removal of the failure check.

These controls show that the finite correspondence suite detects these specific
broken variants. They do not establish general refinement of the TypeScript
implementation to the Lean model, prove untested behavior, or prove the security
of external dependencies or cryptographic operations. The normal proof gate and
its documented assumptions remain the authority for the scope of the model.
